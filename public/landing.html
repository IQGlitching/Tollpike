WHAT TOLLPIKE IS

One control layer between your application and your AI infrastructure.

Your application talks to a single OpenAI-compatible endpoint. Behind it, Tollpike holds every provider, model and route, and decides per request where traffic should actually go.

THE COMPLEXITY

AI traffic gets complicated fast.

Every provider has its own prices, its own latencies, its own quotas, its own failure modes. Wire your application to them directly and the wiring becomes your routing layer: unobserved, unpriced, and one 429 away from an outage.

RESILIENCE

RESILIENCE

One route fails. Traffic re-routes. The system continues.

Failures are isolated to the smallest scope that explains them. A rate-limited model locks for 60s while its siblings keep serving. A bad key cools without touching the provider. Only repeated 5xx trips the provider breaker: 3 failures, 30s, half-open probe.

MODEL LOCKOUT429 → that model rests 60s. Other models on the same key keep serving.
KEY COOLDOWN401/403 → that connection cools. Other keys for the provider keep serving.
PROVIDER BREAKER5xx/network → opens after 3 failures for 30s, then a half-open probe.
model ⊂ connection ⊂ provider · smallest scope wins

HOW IT WORKS

Four stages. One system.

01
Connect

Point any OpenAI-compatible client at one local endpoint: /v1/chat/completions. No SDK, no rewrite.

02
Configure

Declare providers, models, budget caps and routing combos, live from the control panel. No restart.

03
Route

Every request is ordered across all lanes with fallback built in: auto, one of 19 strategies, or a tiered combo.

04
Observe

Traffic, latency, tokens and cost land in the ledger and the control center: per request, per lane, per month.

GET STARTED

Self-hosted. Yours from the first request.

Nothing to sign up for and no account to create. It runs on your machine, binds to loopback, and holds your provider keys locally. Pick an install, add one key, and point the client you already use at it.

01Try it

No install and nothing left behind. Fetches the package and runs the gateway in one command.

npx tollpike
02Install the CLI

State lives in ~/.tollpike, so an upgrade never throws away your usage ledger, budget caps or provider toggles.

npm install -g tollpike
03Docker

For anything long running. Named volume for your data, healthcheck every 30s, restarts after a reboot, and runs as a non-root user in the container.

npm run docker:up
04From source

Clone it and read every line before you run it. That is the point of a gateway that holds your keys.

git clone https://github.com/IQGlitching/Tollpike.git cd Tollpike && npm install && npm start

REQUIRES NODE 18 OR NEWER
NODE 22.5+ ADDITIONALLY ENABLES THE SQLITE-BACKED HALF OF MEMORY RECALL. BELOW THAT IT FALLS BACK TO AN IN-PROCESS INDEX AND SAYS SO.

01
Start it

It binds 127.0.0.1 only. Nothing reaches your network until you deliberately change BIND_HOST, and the control plane is unauthenticated until you set a gateway key, so the default refuses to make that decision for you.

LISTENING ON HTTP://127.0.0.1:20128

02
Open the control center

Twenty pages at /panel. It boots with zero keys configured, every provider reads NO KEY, and the router has nowhere to send traffic. That is the expected first state, not a fault.

03
Add one provider key

Put it in the protected env file, which sits outside the source tree on purpose. Several keys for one provider is a comma separated list, and each becomes an independently cooled connection, so one rate-limited key does not bench the lane. Restart after editing.

printf 'ANTHROPIC_API_KEY=your_key_here\n' >> ~/.tollpike/.env
04
Point your tools at it

Anything that speaks the OpenAI chat-completions format works by changing the base URL. No SDK swap and no code rewrite. Most tools read these two variables, so exporting them is often the whole integration.

export OPENAI_BASE_URL=http://127.0.0.1:20128/v1 export OPENAI_API_KEY=unused
05
Or hand the whole gateway to an agent

The gateway exposes itself as 104 MCP tools across 31 scopes over stdio, so a model can read routing state, inspect spend and drive the control plane. Drop MCP_READ_ONLY to let it spend money and change settings.

{ "mcpServers": { "tollpike": { "command": "tollpike", "args": ["mcp"], "env": { "MCP_READ_ONLY": "true" } } } }
